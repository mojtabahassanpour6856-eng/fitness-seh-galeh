# فهرست نامزدهای هندسی BodyParts3D 4.0

تاریخ: 2026-11-28

این فهرست از کاتالوگ رسمی IS-A نسخه فعلی BodyParts3D استخراج شده است. شناسه‌های FMA و BP در کاتالوگ ثبت شده‌اند؛ وجود فایل OBJ، سالم‌بودن هندسه، صحت سمت و لایه‌بندی هنوز باید با بسته دانلودی رسمی بررسی شود.

## چرا این مرحله مهم است؟
در کاتالوگ رسمی، برای بسیاری از عضلات شناسه مستقل سمت راست و چپ وجود دارد. بنابراین می‌توانیم انتخاب عضله را به مش واقعی متصل کنیم، به‌جای اینکه صرفاً سطح تقریبی را رنگ کنیم.

## دامنه پایلوت
- سینه: سه بخش سینه‌ای بزرگ
- سرشانه: سه بخش دلتوئید و چهار عضله روتاتورکاف/گرد
- بازو: دو سر دوسر، سه سر سه‌سر و براکیالیس
- پشت: سه بخش ذوزنقه‌ای
- لگن و پا: سه عضله سرینی، چهارسر، همسترینگ، نزدیک‌کننده و ساق

فهرست ساختاریافته با FMA ID، representation/BP ID، سمت و جفت احتمالی:
`ANATOMY_BODYPARTS3D_4_CANDIDATES.json`

## هشدارهای صحت
1. «وجود در کاتالوگ» مساوی «هندسه سالم و قابل رندر» نیست.
2. برچسب‌های superficial/intermediate/deep در JSON فعلاً فرضیه اولیه برای سازمان‌دهی است و تا بازبینی هندسه/مرجع آناتومی تأییدشده تلقی نمی‌شود.
3. شناسه‌های زوج چپ و راست فقط نامزد pairing هستند؛ پیش از اتصال به UI باید مختصات و برچسب واقعی OBJ بررسی شوند.
4. این منبع بدن مرجع مرد بالغ است و برای ساخت نمای زنانه استفاده نمی‌شود.
5. هیچ موردی از این فهرست هنوز برای محصول فعال یا وارد نسخه اصلی نشده است.

## منابع رسمی
- کاتالوگ IS-A: https://dbarchive.biosciencedbc.jp/data/bodyparts3d/LATEST/isa_parts_list_e.txt
- صفحه دانلود: https://dbarchive.biosciencedbc.jp/en/bodyparts3d/download.html
- مجوز: https://dbarchive.biosciencedbc.jp/en/bodyparts3d/lic.html

## دروازه پذیرش پیش از هرگونه ادغام
1. دریافت بسته رسمی BodyParts3D 4.0 و ثبت checksum و تاریخ دریافت.
2. تطبیق هر representation ID با فایل OBJ واقعی.
3. بررسی غیرخالی بودن vertices/faces، مختصات محدود و bounds.
4. بررسی محور، واحد، موقعیت فضایی و سمت چپ/راست.
5. رندر مستقل و مقایسه با مرجع آناتومی معتبر.
6. بررسی تقاطع/هم‌پوشانی و ترتیب پوشانندگی قبل از تعیین لایه سطحی/میانی/عمقی.
7. اندازه‌گیری تعداد مثلث‌ها و حجم خروجی و تعیین بودجه عملکرد موبایل.
8. نگه‌داشتن تمام نامزدها خارج از نسخه اصلی تا عبور از همه دروازه‌ها.

## محدوده ایمنی
فقط فایل‌های `experiments/` در شاخه آزمایشی تغییر می‌کنند. هیچ تغییری در `src/`، نسخه اصلی، بانک حرکات، پایگاه داده یا اطلاعات شاگردان انجام نشده است.
